# Графика Second Dawn на Windows: вводная для Claude на компьютере игрока

Ты — Claude Code на Windows-компьютере игрока (RTX 4070 Super, 12 ГБ). Графика мода переехала сюда с Mac
(2026-09-27): здесь видеокарта, поэтому здесь обучение своей модели и 3D-рендер зверей, и здесь же теперь
импорт картинок в мод. Общайся по-русски, коротко. Сначала прочитай:

1. `CLAUDE.md` — правила проекта (обязательны). Главное: игру игрока не трогать без его слова и при
   запущенной игре; коммит, версия и `build.sh` — только по просьбе; публикацию (`tools/publish.sh`)
   запускает сам игрок, ключ из `.env` не читать.
2. `docs/ART-HANDOFF.md` — как устроена графика, конвейер, что сделано, уроки по запросам.
3. `docs/ART-STYLE.md` — блок стиля для всех запросов картинок.
4. `docs/ART.md` — полный список графики.

## Что уже сделано (версии до 0.1.7 на портале)
Иконки всех 77 предметов, картинки всех 82 технологий, 30 зданий эпох 1–3, руды, логова, записка, стена,
излучатель — всё из Codex (gpt-image-2) в стиле `docs/ART-STYLE.md`. Временные картинки остались только у
зверей (вид сверху, повёрнутый на 16 направлений, без шагов — `import_art.py --unit`, `KIN` в `art.lua`).

## Принцип (игрок, 2026-09-27)
Цель — не переделать игру, а дорисовать то, чему в ней нет подходящего. Где ванильная графика подходит по
смыслу — брать её как есть (без перекраски: у неё анимация, повороты, стыки). Своё рисовать только там, где
ванильное не подходит. Предложение (согласовать с игроком перед правкой):
- вернуть ваниль: `sd-lab` → лаборатория; `sd-bronze-drill` → твердотопливный бур; `sd-bronze-arm` →
  твердотопливный манипулятор; `sd-roller-chute`, `sd-underground-chute`, `sd-splitter-chute` → жёлтая лента,
  подземная, разделитель; `sd-swivel-gun` → пулемётная турель. Сейчас у них своя статичная картинка или
  перекраска: убрать строку из `art/manifest.txt` и картинки, в прототипе взять графику ванильного без `tint`;
- своё: деревянные жёлоба, рычажный манипулятор, частокол, копатель и кайловый копатель, самострелы,
  корабли, камеры пробуждения, радиатор, охладитель, звери — ванильного по смыслу нет.

## Что делать здесь
1. **Перенести конвейер на Windows.** `tools/art.sh`, `tools/import_art.py`, `tools/art_preview.py`,
   `tools/render_icons.py` писались под macOS: картинки масштабирует `sips` (в `import_art.py`: `resized`,
   в `art.sh`: конвертация webp/jpg). Заменить на Pillow (`pip install pillow`), `art.sh` — на Python или
   PowerShell. Проверка, что ничего не поменялось: `tools/art.sh` без аргументов переимпортирует всё из
   `art/manifest.txt` — `git diff --stat graphics/` должен показать почти ноль изменений.
   Путь к игре (`GAME` в `import_art.py`, `art_preview.py`, `tools/portal_sheets.py`, тестах) — вынести
   в одну настройку: здесь Factorio стоит в Steam по Windows-пути.
2. **Звери** (решение игрока 2026-09-27: свои, в нашем стиле, на RTX). Полный авто-конвейер (Codex-фото →
   3D-реконструкция → UniRig скелет+скин) не доехал: скелет получается нормальный, а веса скина у UniRig —
   `NaN` на каждой вершине (баг апстрима, не наш; см. `sd-3d-animals/README.md`). **Рабочий путь, которым
   реально сделан `sd-wolf`: мэш+риг+анимация готового CC0-донора (Quaternius) со своей перекраской по
   вершинам**, камера и тень как в Factorio, 16 направлений × N кадров, отдельная честная тень (рендер в
   Cycles через shadow catcher, не `draw_as_shadow`-трюк на плоском силуэте). Весь рецепт, параметры и
   КАЖДАЯ грабля, на которую уже наступали (экспозиция, направление тени, материалы FBX, bound_box без позы
   и т.д.) — **`sd-3d-animals/PIPELINE.md`, прочитать перед следующим зверем**. Production-скрипты там же:
   `render_wolf_sheet.py` (рендер) + `compose_sheet.py` (сборка в лист). Листы → `graphics/entity/sd-<зверь>/`,
   подключение — ветка зверей в `prototypes/art.lua` (`FRAMES`, `KIN`, `BOOST`).
   Звери: волк — готов; вожак (крупнее) — тот же лист, другой масштаб; кабан, секач, медведь, медвежонок —
   не начаты, нет подходящего реалистичного CC0/CC-BY донора (Gobkit слишком мультяшный).
3. **Остальное с анимацией или поворотом** — тем же 3D-конвейером после зверей (сейчас перекрашенная ваниль
   или упрощённо):
   - манипуляторы `sd-lever-arm`, `sd-bronze-arm` (части руки: основание, рука, захват);
   - жёлоба `sd-wooden-chute`, `sd-wooden-underground-chute`, `sd-wooden-splitter-chute`, `sd-roller-chute`,
     `sd-underground-chute`, `sd-splitter-chute` (анимация ленты по направлениям, как у ванильных лент);
   - корабли `sd-tug`, `sd-screw-steamer`, `sd-barge`, `sd-fluid-barge` (64 направления);
   - турели `sd-crossbow`, `sd-swivel-gun`, `sd-repeating-crossbow` — сейчас не поворачиваются (ветка
     `ammo-turret` в `art.lua`), нужна голова на 64 направления поверх основания;
   - частокол `sd-palisade` — сейчас отдельные блоки, нужны стыки как у ванильной стены;
   - копатели `sd-digger`, `sd-pick-digger`, `sd-bronze-drill` — одна картинка на все направления, без работы;
   - облик игрока по одежде (кожаная куртка, шуба, лёгкая накидка, скафандр).
4. **Своя модель (эксперимент, не основной путь)** — проект `factorio-lora` (отдельный репозиторий):
   LoRA на оригинальной графике игры (base + space-age), **только** на ней — не на картинках Codex. Модель
   не публиковать. На Mac был mflux (только Apple Silicon); здесь — ai-toolkit/OneTrainer/diffusers под CUDA.
   Результаты Mac-прогона — в его `README.md`.

## Что осталось только на Mac
Обученная LoRA (`factorio-lora/train/`, 1.8 ГБ), локальные модели FLUX (`~/models`), вход в Codex и
Hugging Face — не в git. Набор для обучения собирается заново из файлов игры (`tools/build_dataset.py`,
путь к игре поправить под Windows). Скачивания, установки и входы в аккаунты — только с согласия игрока.

## Картинки через Codex
Основной источник рисованной графики — Codex CLI с личным аккаунтом игрока (не рабочим!): на Mac это
`CODEX_HOME=~/.codex-personal`; здесь игрок залогинит Codex сам. Лимиты: 5-часовое окно и неделя, картинки
съедают много — `-c model_reasoning_effort=low`, пачками по ~15, параллельно до 4. Образцы стиля: арбалет
`art/reference/crossbow-icon.png` + лист ванильных иконок/зданий/технологий (собрать из файлов игры).
